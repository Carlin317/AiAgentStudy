# 15 - LCEL 与链式调用

---

**本章课程目标：**

- 理解 **Runnable** 的定位，知道 LangChain 为什么要把 Prompt、Model、Parser、Tool、Chain 都抽象成统一的“可执行组件”。
- 理解 **LCEL**（LangChain Expression Language，LangChain 表达式语言）到底解决了什么问题，掌握 `|` 管道符背后的链式组合思想。
- 能读懂并运行本章全部案例：**顺序链、分支链、多步串行链、并行链、函数链**，建立后续学习 [记忆与对话历史](/stage3-framework/ch16)、[Tools 工具调用](/stage3-framework/ch17)、[RAG](/stage3-framework/ch19)、[Agent](/stage3-framework/ch21) 的基础。

**学习建议：** 建议先跑通 `prompt | model | parser`，再看分支、并行和自定义函数节点。读代码时关注两点：每个 Runnable 收什么、吐什么；组合后能否继续被 `invoke`、`stream`、`batch` 调用。

## 1、Runnable 与统一调用方式

### 1.1 前置知识点：抽象基类（ABC）

**Runnable** 是 LangChain 的核心抽象接口。所有组件——Prompt、Model、Parser、Chain——都实现它，统一提供 `invoke`、`batch`、`stream` 等方法。

抽象基类（ABC）的作用是：先规定一类对象应具备哪些能力（如单次调用、批量调用、流式调用），但不规定每个对象的内部实现。Runnable 就是 LangChain 用 ABC 定义的那个统一接口——只要实现了 Runnable，就能用同一套方式调用。

![`langchain_core.runnables.base` 中 Runnable 的类定义与职责说明：可 invoke/batch/stream 并支持组合 (images/15/15-1-1-1.jpeg)](/images/15/15-1-1-1.jpeg)

> **图意说明**：上图截自 LangChain 参考文档。`Runnable` 声明为 `class Runnable(ABC, Generic[Input, Output])`，描述的是“可被调用、批量处理、流式输出、变换与组合”的工作单元；`invoke`/`ainvoke`、`batch`/`abatch`、`stream`/`astream` 等成对出现，`astream_log` 还可流式透出部分中间结果。各方法均可传入 `config`（如标签、元数据）便于追踪与排障；输入/输出/config 的结构信息可通过 `input_schema`、`output_schema`、`config_schema` 等暴露给工具链与 IDE。

### 1.2 为什么 LangChain 需要统一接口

没有统一接口时，Prompt、模型、解析器、工具各自一套入口（`format`、`generate`、`parse`、`run` 混用），导致组件难拼接、替换实现时到处改代码。Runnable 把所有”能接收输入并产生输出”的对象统一到同一接口下。

### 1.3 定义

Runnable 是 LangChain 中”可执行数据处理节点”的统一接口。区分两个概念：

- **Runnable**：统一抽象标准，表示”这一类对象是可执行组件”
- **统一调用方式**：Runnable 带来的结果——这些组件都支持 `invoke`、`batch`、`stream`、`ainvoke`、`abatch`、`astream`

LangChain 中已学过的对象都是 Runnable：[Prompt 模板](/stage3-framework/ch13)、[聊天模型](/stage3-framework/ch11)、[输出解析器](/stage3-framework/ch14)，以及后续的检索器、工具、整条链，甚至编译后的 LangGraph 图。组件能顺畅串成链，是因为**它们本身都被设计成了可组合的 Runnable**。

### 1.4 为什么需要统一调用方式

统一调用方式是链式组合成立的基础。以三个典型对象为例：

**1. Prompt 模板**

- 业务层面常用 `format(...)`，但在 LCEL 中统一用 `invoke(...)`

```python
# 业务层面常见写法
prompt_str = prompt.format(topic="LangChain")

# LCEL 统一接口写法
prompt_value = prompt.invoke({"topic": "LangChain"})
```

**2. 模型**

- 接收 Prompt 输出，返回 `AIMessage`

```python
ai_message = model.invoke(prompt_value)
```

**3. 解析器**

- 业务层面常用 `parse(...)`，在 LCEL 中统一通过 `invoke(...)` 接收上一步结果

```python
result = parser.invoke(ai_message)
```

三步统一为同一风格：

```python
prompt_value = prompt.invoke({"question": "什么是 LangChain？"})
ai_message = model.invoke(prompt_value)
result = parser.invoke(ai_message)
```

统一接口的价值：组件易替换、流程易串联、链本身可继续作为组件使用、中间结果传递无需手写适配代码。这是 `prompt | model | parser` 能成立的根本原因。

### 1.5 常用方法

实现了 Runnable 接口的对象，通常都支持下面这些核心方法：

| 方法               | 作用                       | 适合场景                   |
| ------------------ | -------------------------- | -------------------------- |
| `invoke(input)`    | 同步处理单个输入           | 最常用，单次调用           |
| `batch(inputs)`    | 同步批量处理多个输入       | 批量任务、离线任务         |
| `stream(input)`    | 同步流式处理               | 打字机输出、长文本生成     |
| `ainvoke(input)`   | 异步处理单个输入           | 异步服务、高并发           |
| `abatch(inputs)`   | 异步批量处理               | 异步批量任务               |
| `astream(input)`   | 异步流式处理               | 异步聊天 UI、流式返回      |
| `astream_log(...)` | 流式输出并可选带上中间步骤 | 调试链、观察多节点执行过程 |

`invoke` 是最基础的”执行一次”，其他方法是在同步/异步、单条/批量、一次性/流式维度上的扩展。**Prompt、Model、Parser、Chain 都支持 invoke，不是因为它们相同，而是因为它们遵守同一套调用协议。**

### 1.6 在实际项目中的价值

实际项目中，一个企业问答系统可能从 `prompt + model` 起步，逐步加上 parser、branch、parallel、lambda。没有 Runnable 抽象，每增一步都要大改；有了它，变化只是往链上加节点。后续的检索器、工具、记忆模块乃至 LangGraph 节点，都建立在 Runnable 之上。

## 2、LCEL 简介

### 2.1 定义

**LCEL** 是 **LangChain Expression Language** 的缩写，中文通常叫 **LangChain 表达式语言**。它的作用很直接：**用一种声明式、可组合的方式，把多个 Runnable 连接起来。**

最经典的 LCEL 写法就是：

```python
chain = prompt | model | parser
result = chain.invoke({"question": "什么是 LangChain？"})
```

LCEL 提供了一套用管道符或其他组合方式把多个 Runnable 连接起来的表达方法。

但 LCEL 不只是“把对象连起来”，它还在帮我们做两件事：

- 把前一步输出自动传给后一步
- 尽量减少不同节点之间手写适配的样板代码

### 2.2 LCEL 不只是语法糖

LCEL 的价值不只是省代码，有三层好处：

**1. 表达更清晰**

传统写法：

```python
prompt_value = prompt.invoke({"question": "什么是 LangChain？"})
ai_message = model.invoke(prompt_value)
result = parser.invoke(ai_message)
```

LCEL 写法：

```python
chain = prompt | model | parser
result = chain.invoke({"question": "什么是 LangChain？"})
```

第二种写法把流程结构表达得更清楚。

**2. 更容易组合**

LCEL 连接出来的结果本身还可以继续参与组合：顺序链可以放进分支链或并行链，并行链输出可以继续交给下一步。LCEL 自动处理前后步骤的结果传递，只有输入输出结构不匹配时才需要插入 `RunnableLambda` 做映射。

**3. 统一支持同步、异步、批量、流式**

`RunnableSequence` 和 `RunnableParallel` 自动继承 Runnable 的同步、异步、批量、流式能力，组合后仍可统一执行。

### 2.3 LCEL 的核心组合思想

LCEL 背后的核心组合思想：

- **顺序组合**：前一步输出作为下一步输入
- **条件路由**：根据输入选择不同链
- **并行组合**：同一输入同时喂给多条链

**RunnableSequence** 和 **RunnableParallel** 是两种核心组合原语，其他 Runnable 结构可视为它们的扩展。`RunnableLambda` 则在组合过程中插入自定义 Python 逻辑（调试、映射、整理、判断）。

LCEL 的本质是**用数据流编排的方式思考 LLM 应用**。

### 2.4 LCEL 和 Chain 的关系

容易混淆的两个概念：**LCEL** 是构建流程的表达方式（怎么写），**Chain** 是构建出来的可执行流程（得到什么）。

## 3、Chain 结构

### 3.1 定义

在 LangChain 语境里，**Chain（链）** 可以简单理解成：**把多个 Runnable 按某种规则组合起来后，形成的一段可执行流程。**

这段流程可以很简单，也可以很复杂：

- 简单时，就是 `prompt | model`
- 常见时，是 `prompt | model | parser`
- 复杂时，可能是分支 + 并行 + 自定义函数节点混合组成的流程

**链本身也是 Runnable**，可以继续参与组合：顺序链可以作为分支链的分支，也可以放进并行链，并行结果还可以交给后续节点处理。

### 3.2 典型结构

结合 [第 13 章](/stage3-framework/ch13)、[第 11 章](/stage3-framework/ch11)、[第 14 章](/stage3-framework/ch14)，最典型的链是：

1. **Prompt**：组织输入
2. **Model**：调用模型生成结果
3. **Parser**：把结果解析成业务更容易使用的形式

也就是：

```python
chain = prompt | model | parser
```

这是 LangChain 里最经典、最基础的组合方式。

## 4、链式调用基础用法与案例

### 4.1 几种链的选择与对比

| 类型           | 典型写法 / 类名                                | 执行方式               | 输入 → 输出     | 典型场景                     |
| -------------- | ---------------------------------------------- | ---------------------- | --------------- | ---------------------------- |
| **顺序链**     | `prompt ｜ model ｜ parser`/`RunnableSequence` | 一步接一步执行         | 单输入 → 单输出 | 最基础的问答、抽取、摘要     |
| **分支链**     | `RunnableBranch(...)`                          | 按条件只走其中一条子链 | 单输入 → 单输出 | 意图路由、多语言路由         |
| **多步串行链** | 多条子链继续用 `｜` 串联                       | 前一步结果给后一步     | 单输入 → 单输出 | 先总结再翻译、先整理再生成   |
| **并行链**     | `RunnableParallel({...})`                      | 多条子链同时执行       | 单输入 → 多输出 | 中英文同时生成、多模型并跑   |
| **函数链**     | `RunnableLambda(func)`                         | 在链中插入 Python 函数 | 取决于函数      | 字段映射、调试、轻量业务逻辑 |

快速选择：直线流程用顺序链；按条件切换用分支链；前后步骤依赖用多步串行链；同一输入多路处理用并行链；插入自定义逻辑用函数链。

---

### 4.2 RunnableSequence（顺序链）

`RunnableSequence` 是最常见的链类型，几乎出现在所有基础链式流程中。核心规则：**前一个 Runnable 的输出，直接作为后一个 Runnable 的输入。**

所以：

```python
chain = prompt | model | parser
```

本质上就是一个 `RunnableSequence`。

你也可以显式写成：

```python
from langchain_core.runnables import RunnableSequence

chain = RunnableSequence(first=prompt, middle=[model], last=parser)
```

实际开发中更推荐管道符写法，可读性更好。典型场景就是把 Prompt 组织输入、Model 调用模型、Parser 解析输出一次性串起来。

### 4.3 RunnableBranch（分支链）

如果顺序链解决的是“按顺序做”，那么 `RunnableBranch` 解决的就是：**根据输入内容，决定走哪条链。**

类似编程中的 `if / elif / else`，但在 Runnable 体系中。典型结构：

```python
RunnableBranch(
    (条件1, 链1),
    (条件2, 链2),
    默认链,
)
```

执行时会依次判断条件：

- 第一个命中的条件对应的链会被执行
- 如果都不命中，就走默认链

常见场景：根据语言选择翻译链、根据意图选择客服流程、根据问题类型选择 Prompt 或模型。

本章案例是一个语言路由示例：

- 输入里有“日语”关键词，走日语翻译链
- 输入里有“韩语”关键词，走韩语翻译链
- 否则默认走英语翻译链

### 4.4 Multi-Step Chain（多步串行链）

多步串行链把多条子链首尾串起来。案例做的事：

1. 先让模型用中文介绍某个主题
2. 再把第一步结果转换成第二步所需的输入结构
3. 最后再交给另一条链翻译成英文

这是典型的”多步加工”：第一步不是最终结果，第二步依赖第一步，中间可能需要结构映射。常见场景如先摘要再翻译、先提取要点再生成报告。

### 4.5 RunnableParallel（并行链）

`RunnableParallel` 解决的是**同一份输入同时交给多条链处理**的需求。多条子链共享输入、并发执行，结果按键汇总成 `dict`。

例如：

```python
parallel_chain = RunnableParallel({
    "chinese": chain1,
    "english": chain2,
})
```

LCEL 还支持**直接用字典表达并行结构**：

```python
parallel_then_summary = {
    "paragraph_1": chain1,
    "paragraph_2": chain2,
} | summary_chain
```

含义：先并行运行 `chain1` 和 `chain2`，汇总成字典，再交给 `summary_chain`。适合”并行生成多个结果后统一分析”的场景。

返回结果形如：

```python
{
    "chinese": "...",
    "english": "..."
}
```

`RunnableParallel` 是与 `RunnableSequence` 并列的核心组合原语。常见场景：同时生成中英文答案、多模型对比、多维度分析。

### 4.6 RunnableLambda（函数链）

`RunnableLambda` 把普通 Python 函数变成 Runnable，用于处理链中常见的中间需求：上一步输出结构与下一步不匹配、打印中间结果调试、字段重命名、插入简单业务逻辑。没有它就得把链拆开手写中间处理代码。

例如：

```python
from langchain_core.runnables import RunnableLambda

def debug_print(x):
    print(x)
    return {"input": x}

chain = chain1 | RunnableLambda(debug_print) | chain2
```

LangChain 还支持直接把函数放在 `|` 中间，框架自动包装成 Runnable。案例同时演示了 `chain1 | debug_print | chain2` 和 `chain1 | RunnableLambda(debug_print) | chain2` 两种写法。

### 4.7 补充：其他常见 Runnable 结构

除了本章重点展开的几种结构，LangChain 里还有一些在实际项目里很常见、但初学阶段不必深入的 Runnable 组件。

| 名称                    | 作用                                                    | 什么时候会用到                               |
| ----------------------- | ------------------------------------------------------- | -------------------------------------------- |
| `RunnablePassthrough`   | 接收输入后原样透传，也可顺手往输出中补充字段            | 想保留原始输入、给结果加键、做轻量上下文拼装 |
| `RunnableWithFallbacks` | 为某个 Runnable 配置兜底逻辑，失败后回退到备用 Runnable | 模型调用失败、主链失败后自动切备用方案       |
| `RunnableBinding`       | 为 Runnable 预绑定 `config`、默认参数等                 | 同一链在不同环境复用、可配置温度与模型等     |

Runnable 体系不只有顺序、分支、并行、lambda，LangChain 提供了完整的可执行节点家族。

**章节思考题：**

1. LCEL 帮你解决的不是“少写几行代码”，而是什么问题？

   **参考思路：** 让输入格式化、模型调用、解析、分支、并行和后处理都变成可组合的 Runnable。重点是流程结构清晰、可复用、可流式、可批处理。

2. 读一条 LCEL 链时，你会如何判断每一段是否设计合理？

   **参考思路：** 看每个 Runnable 的输入输出是否清楚、是否只做一类事、是否方便单独测试。链路问题多数不是模型错，而是前后节点数据结构没对上。

3. `RunnableLambda` 什么时候是好用的胶水，什么时候会变成坏味道？

   **参考思路：** 少量字段转换、清洗、路由判断适合用它；大量业务逻辑、外部副作用和复杂异常处理应拆成独立函数或服务。

4. 遇到“先分类、再分流、部分并行、最后汇总”的任务，你会如何拆链？

   **参考思路：** 顺序链分类、分支链选路、并行链同时处理、汇总节点统一输出。先画数据流再写 LCEL。

**本章小结：**

- **Runnable** 是 LangChain 统一的”可执行组件”抽象，Prompt、Model、Parser、Tool、Chain 都遵守同一接口。
- **LCEL** 把多个 Runnable 组合成链，核心价值是让流程声明式、可组合、可扩展。
- **链的核心主线** 是把 [提示词模板](/stage3-framework/ch13)、[模型调用](/stage3-framework/ch11)、[输出解析器](/stage3-framework/ch14) 组织成可执行流程。
- **五类常见链**：顺序链是基础，分支链解决路由，多步串行链解决步骤依赖，并行链解决多路处理，RunnableLambda 插入自定义逻辑。
- 学完本章应能读懂并写出 `prompt | model | parser` 链，区分五类链的使用场景。
